- 低优先级：作为 Windows 用户推荐工具

- 高优先级：AIX Box 管理界面参考 Rust 架构

**一句话**：WSL Dashboard 对 AIX 核心业务无直接影响，但验证了"低门槛系统管理工具"是刚需。

### Nate Herk工具选择方法论（2026-05-11）

**来源**：用户377861分享

**核心洞察**：每次换工具效率先跌20%

#### 四档工具分类法

| 档位 | 定义 | Nate的工具栈 |
|------|------|-------------|
| S档 | 每天必用 | Claude Code（操作系统）、VS Code（壳）、Glaido（语音） |
| A档 | 每周用 | Codex、Claude Chat、Hermes Agent、Perplexity、Grok |
| B档 | 专家工具 | Nano Banana 2、GPT Image 2、kie.AI、HeyGen、11 Labs |
| C档 | 观察 | Gemini、Ollama、Manus |
| 毕业 | 被覆盖 | ChatGPT、OpenClaw、Cursor、Notebook LM、n8n、Wispr Flow |

**关键发现**：Cursor在毕业堆——功能被Claude Code + Codex覆盖，不换而是"因为被覆盖而毕业"

#### Coding Agent本质

**Nate判断**："Coding agents只是harness（外壳）"
- Claude Code、Codex、OpenClaw、Hermes = 不同外壳
- 底层都是：在一个目录里工作
- **真正有价值**：CLAUDE.md、技能脚本、项目架构

**核心观点**：
> "我不知道Claude Code六个月后是不是还是第一。你也不知道。但项目本身，会留下来。"

**对AIX启示**：
- 目录结构 > 工具选择
- 技能脚本、Agent流程、CLAUDE.md是核心资产
- 工具可以被替换，资产是自己的

#### 20%代价计算法

**换工具成本**：效率先跌20%

**三种可能**：
1. 跌完效率比之前高 → 值得换
2. 跌完效率回到原点 → 没意义
3. 跌完效率比之前低 → 别换

**核心问题不是**："这个工具有没有某个功能"
**而是**："换来的效率提升，能不能抵消学习时间 + 20%损失"

#### 过滤新工具的问题

**一个问题**：它现在能解决你有的一个痛点吗？

- 答案"不" → 收藏链接，今天别动工作流
- 答案"是" → 用真实低风险任务测试，一周后看是否赚到日常工具位

#### 与AIX技术栈的关联

| Nate方法论 | AIX实践 |
|-----------|--------|
| 目录结构 > 工具外壳 | 九层架构可替换组件 |
| 任务驱动工具无关 | 一人公司10能力栈按任务选工具 |
| 20%代价计算 | Coin Hour成本效益分析 |
| 北极星过滤噪音 | 数字主权 = 北极星 |

**一句话**：Nate验证了AIX的技术栈设计思路——不锁定工具，锁定目录和流程。

### 用户377861深度拆解：越南RWA的真实逻辑

**为什么是越南？**
- 不是理想主义，是现实倒逼的创新
- 银行不投 → 政府没钱 → 开数字资产闸 → 全球资本进场
- "被逼出来的创新"

**RWA逻辑成立的前提**：
```
光伏电站 → 未来10年电费收入 → 拆成1万份代币 → 全球投资者购买
```
- 核心价值：门槛资产 → 流动性资产
- 前提：电费收入稳定可预测
- 光伏/风电满足：PPA购电协议、现金流稳定、数据公开透明
- 比DeFi"挖矿收益"真实得多

**三大风险（文章没说透）**：

1. **黑钱问题**
   - 越南玩家部分资金来自散户+帮派黑钱
   - 洗钱通道：黑钱买入RWA → 持有一段时间 → 卖出换成干净的钱
   - 越南想脱离FATF灰名单 → 监管收紧 → 灰色资金撤离 → 代币价格崩

2. **资产穿透问题**
   - 电站真的发电了吗？
   - 发了多少电？
   - 电费真的收到了吗？
   - 收入真的进到代币持有者账户了吗？
   - 需要第三方审计+链上验证
   - 如果只是"包装成RWA的空气币" = DeFi泡沫翻版

3. **汇率风险**
   - 电费收入是越南盾 → 代币定价用什么？
   - 用USDT/USDC → 汇率波动谁来承担？
   - 这不是技术问题，是金融工程问题

**两个验证点决定成败**：
1. 现金流验证：电费收入是否真实穿透到代币持有者
2. 合规验证：越南政府是否真的愿意为RWA背书，而不是收割一波

**一句话**：如果两个验证点都成立，越南会成为"Web3+新能源"样板间；否则就是另一场泡沫。

## Agent Skills设计模式：Google 5模式分析（2026-05-05）

**来源**：用户377861分享  
**作者**：若飞（架构师）  
**参考**：Google Cloud Tech《5 Agent Skill design patterns》

### Google 5个模式

| 模式 | 解决问题 | 本质 |
|------|---------|------|
| Tool Wrapper | Agent不懂某领域 | 按需加载的领域手册 |
| Generator | 输出结构不稳定 | 带模板的填空流程 |
| Reviewer | 审查标准混乱 | 可替换的评分清单 |
| Inversion | 需求没问清就生成 | 需求访谈器 |
| Pipeline | 复杂任务跳步骤 | 带检查点的工作流 |

### 核心判断

**Anthropic解决了容器，Google补上了模式**：
- 格式：SKILL.md怎么写（Anthropic）
- 机制：怎么加载、触发（Anthropic）
- 模式：内部工作流怎么设计（Google）

**Skill是"过程资产"**：
> "过去写在手里、脑子里、团队习惯里的工作方式，正在被写成Agent可执行的接口"

### 5个模式对应5类失败

| 失败类型 | 模式 |
|---------|------|
| 缺领域知识 | Tool Wrapper |
| 输出漂移 | Generator |
| 检查标准混乱 | Reviewer |
| 需求没问清 | Inversion |
| 复杂流程跳步骤 | Pipeline |

### 对AIX的帮助

**1. agentskills.io组织**

```
agentskills.io/
├── tool-wrappers/   # 领域知识
├── generators/      # 模板生成
├── reviewers/       # 审查评分
├── inversions/      # 需求访谈
└── pipelines/       # 多阶段流程
```

**2. 一人公司Agent技能栈**

| Skill类型 | 应用 | Coin Hour |
|----------|------|-----------|
| Tool Wrapper | 行业知识 | 2-5 CH |
| Generator | 报告生成 | 3-5 CH |
| Reviewer | 代码审查 | 5-10 CH |
| Inversion | 需求分析 | 10-20 CH |
| Pipeline | 发布流程 | 10-50 CH |

**3. 和xmemory关系**

- xmemory：存储Skill执行历史
- Skill：可复用工作单元
- Graphify：Tool Wrapper的数据源

### Skill和Harness的关系

> "Skill是Harness可以按需加载的过程模块"

| Harness | Skill |
|---------|-------|
| 运行时主循环 | 可加载过程模块 |
| 上下文管理 | 领域知识注入 |
| 工具调用 | 工作流设计 |
| 错误反馈 | 失败处理 |

### 写Skill的6个问题

1. 触发边界（description）
2. 模式判断（5种选1）
3. 内容拆分（references/assets/scripts）
4. 检查点（哪些步骤停下来）
5. 失败处理（失败后怎么走）
6. 版本治理（审查、变更记录）

### 团队Skill治理

| 来源 | 信任策略 |
|------|---------|
| 官方内置 | 较高信任 |
| 团队自写 | review+测试 |
| Agent生成 | 默认草稿 |
| 社区第三方 | 默认不信任 |
| 带脚本 | 按可执行代码对待 |

### 关键引用

> "SKILL.md是Markdown，但它会影响Agent的行为。只要Agent能调工具、读文件、改代码、发请求，Skill就可能间接影响真实系统。"

> "如果某条规则每次都要成立，更适合用Hook这类确定性机制强制，而不是只写在提示或Skill里。"

> "Agent时代的架构师，不能只看模型，也不能只追框架。更耐用的能力，是把这些工作流拆成边界清楚、可组合、可观测、可回滚的系统部件。"

**一句话**：Google的5个模式补上了Skill的内容设计语言，AIX的agentskills.io可以按此组织，一人公司Agent的技能栈可以按此分类，Coin Hour结算不同模式的调用成本。

- 历史类比：PC之于手写、Excel之于计算器

**3. 商业模式转型**：
- 以前：卖token
- 现在：卖workflow（数字员工）

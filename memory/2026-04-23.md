## Anthropic Skill-Creator 评测机制分析

**时间**: 2026-04-23  
**来源**: Jane提问  
**原文**: https://github.com/anthropics/skills/tree/main/skills/skill-creator

### 核心机制

**评测即资产化**
- 每个Skill通过标准化评测产出量化指标
- 评测结果可对比、可追踪、可改进
- Skill从"代码文件"升级为"可迭代产品"

**迭代闭环**
```
创建Skill → 运行评测 → 获得分数 → 分析问题 → 优化Skill → 重新评测
     ↑                                                      ↓
     └──────────────── 分数提升 = 资产增值 ◄─────────────────┘
```

### 对AIX Skill Store的5大帮助

| 维度 | Anthropic方案 | AIX应用建议 |
|------|--------------|------------|
| **质量门槛** | 评测分数决定Skill上架资格 | Skill Store引入星级评分(1-5星)，<3星需改进 |
| **定价依据** | 高分Skill可溢价 | 评测分数×使用率 = 定价系数，优质Skill可溢价50% |
| **开发者激励** | 评测排名驱动优化 | 月度"Skill排行榜"，TOP10获CH奖励+流量倾斜 |
| **用户信任** | 透明分数降低选择成本 | 展示"准确率/延迟/安全分"三维指标 |
| **资产化** | Skill可版本化迭代 | Skill NFT化，版本升级=资产增值 |

### 具体实施建议

**Phase 1: 评测基础设施**
- 建立AIX Skill评测框架(参考skill-creator)
- 定义三维度评分：功能完整性(40%)、安全合规(30%)、性能效率(30%)
- 自动化测试沙盒(隔离运行环境)

**Phase 2: 资产化运营**
- Skill上架需通过基准测试(如Turix微信自动化需测试10个场景)
- 评测报告公开透明(用户可见详细测试用例)
- 版本迭代需重新评测，分数提升触发CH奖励

**Phase 3: 市场机制**
- 高分Skill进入"精选区"
- 开发者可抵押AIX发布Skill(反垃圾)
- 用户消费Skill的CH按评测分数比例分配给开发者

**关键洞察**
> "评测不是成本，是Skill资产化的基础设施——它让无形的代码变成有价的、可比较、可信任的商品。"

## Karpathy autoresearch（AI自主科研）

**时间**: 2026-04-23
**来源**: Jane分享
**GitHub**: https://github.com/karpathy/autoresearch
**Stars**: 75k+

### 核心设计
- 630行Python，单GPU运行
- Agent自主改train.py，跑5分钟实验，keep/discard循环
- 人只改program.md（规则文件），不改代码
- prepare.py不可修改（确定性底层）
- NEVER STOP：Agent永不停止，人类睡觉Agent干活
- val_bpb为唯一评估指标，固定时间预算使实验可比较

### 与AIX三层映射
| autoresearch | AIX Box | 性质 |
|-------------|---------|------|
| prepare.py（不可修改） | UTXO账本+Coin Hour算法 | 不可篡改底层 |
| program.md（人写规则） | Harness规则 | 确定性边界 |
| train.py（Agent改） | Pico Claw执行层 | AI自主行动区 |

### 核心启发
1. **program.md = Harness**：人不改代码，人改规则文件——"代码做主"的Karpathy版
2. **固定时间预算 = Coin Hour计量**：硬约束让AI行为可预测
3. **NEVER STOP + keep/discard = 涌现机制**：大量"无用实验"偶然组合出突破
4. **results.tsv = 操作审计**：每次操作可追溯、可评估

## TuriX-CUA（视觉驱动AI操作员）

**时间**: 2026-04-23
**来源**: Jane分享
**GitHub**: https://github.com/TurixAI/TuriX-CUA
**Stars**: 2526
**License**: MIT

### 核心特性

- 突破微信等封闭应用限制，实现自动化交互
- OSWorld排行榜第3名（64.2%），Mac基准80%+
- 多智能体架构：brain（VLM视觉理解）→ actor（动作执行）→ memory（记忆压缩）→ planner（任务规划）
- 支持MCP协议，可接入Claude等外部Agent
- Skills系统：markdown playbook，planner选skill，brain执行
- 支持macOS/Windows/Linux
- 已有OpenClaw Skill（clawhub.ai/Tongyu-Yan/turix-cua）
- 支持Ollama本地模型

### 多智能体架构
```
brain_llm → VLM视觉理解（看屏幕）
actor_llm → 动作执行（点击/输入）
memory_llm → 记忆压缩（上下文管理）
planner_llm → 任务规划+Skill选择
```

### 与AIX Box融合分析

**✅ 可以融入——AIX Box的"数字肢体"**

1. **封闭应用突破 = Box广告点击的核心能力**
   - 微信等封闭App无法用API操作
   - TuriX用视觉方式直接操作，绕过API限制
   - AIX Box的自动点击广告收益需要这种能力

2. **多智能体架构 = "LLM打工，代码做主"的实践**
   - brain做语义理解（看）
   - actor做执行（做）
   - 确定性部分（动作序列）可以代码化

3. **Skills系统 = AIX Skill Store的原型**
   - markdown playbook格式
   - planner只看name+description选skill
   - brain看完整指令执行
   - 和AIX Skill Store的三维评测体系可对接

4. **已有OpenClaw Skill = 部署门槛低**
   - 已发布到ClawHub
   - 可直接在OpenClaw环境中使用

5. **本地模型支持 = 数字主权兼容**
   - 支持Ollama本地部署
   - 视觉理解可用Qwen3-VL等本地模型

**⚠️ 融合障碍**

1. **J1900算力不足**：VLM推理需要GPU，Box跑不动视觉模型
2. **brain需要跑在M4**：视觉理解=推理中枢的工作，Box只做执行
3. **精度问题**：64.2%成功率不够金融级操作，Coin Hour交易需要更高确定性
4. **延迟**：视觉识别+动作执行的端到端延迟较高

**🔧 融合方案**

```
Mac mini M4（推理中枢）：
  brain_llm → Qwen3-VL本地视觉理解
  planner_llm → 任务规划+Skill选择
  memory_llm → 上下文管理

AIX Box（边缘节点）：
  actor执行 → 接收M4指令，执行确定性动作
  Harness校验 → 动作是否合规（不能转账给未授权地址等）
  UTXO记账 → 动作结果原子记录
```

**那耶村场景**：
- Box自动操作微信接单（封闭App突破）
- Box自动点击广告产生收益
- Box自动处理村民常见请求（查余额、转账）
- 关键操作（转账）由Harness拦截+确认

**一句话**：TuriX-CUA是AIX Box的"数字手"——视觉驱动的操作能力让Box突破封闭应用壁垒，但视觉理解需跑在M4，Box只做确定性执行层

## GenericAgent（3K行自我进化Agent框架）

**时间**: 2026-04-23（实际是24日凌晨）
**来源**: Jane分享
**GitHub**: https://github.com/lsdefine/GenericAgent
**Stars**: 6475
**arXiv**: 2604.17091
**License**: MIT

### 核心特性
- ~3K行核心代码，~100行Agent Loop
- 9原子工具：code_run、file_read、file_write、file_patch、web_scan、web_execute_js、ask_user、update_working_checkpoint、start_long_term_update
- 自我进化机制：新任务→自主摸索→固化Skill→写入记忆→下次直接调用
- 分层记忆系统：L0（Meta规则）→ L1（索引）→ L2（全局事实）→ L3（任务Skill/SOP）→ L4（会话归档）
- Token高效：<30K上下文，其他Agent需要200K-1M，成本低一个数量级
- 已有百万级Skill库
- 支持浏览器/终端/文件系统/键鼠/屏幕视觉/移动设备（ADB）
- 支持微信/QQ/飞书/企业微信/Telegram作为Bot前端

### 自我进化流程
```
新任务 → 自主摸索（安装依赖、编写脚本、调试验证）
       → 固化为Skill
       → 写入记忆层
       → 同类任务直接调用
```

### 与今天其他项目的关系

| 项目 | 核心创新 | 和GenericAgent关系 |
|------|----------|-------------------|
| autoresearch | program.md规则文件 | GenericAgent的Meta规则（L0）类似，但更动态 |
| TuriX-CUA | 视觉驱动多智能体 | GenericAgent的9工具涵盖TuriX能力，但无专门VLM分层 |
| gbrain | 零LLM知识图谱 | GenericAgent的L3 Skill类似gbrain的页面，但更轻量 |
| llm_wiki | 两步思考Ingest | GenericAgent的"固化Skill"类似，但自动化程度更高 |
| UniToolCall | 统一工具调用 | GenericAgent的9工具更原子，但格式未统一 |

### 与AIX Box融合分析

**✅ 核心契合——3K行代码+自我进化 = "代码做主"的极致**

1. **9原子工具 = Pico Claw基础能力集**
   - code_run：执行确定性脚本
   - file_read/write：本地存储操作
   - web_scan：网络交互
   - ask_user：关键操作人工确认（天然符合Harness逻辑）
   - 正好对应Box需要的能力

2. **自我进化 = Skill Store的自然增长**
   - 每次解决新任务自动生成Skill
   - 无需人工预设，能力随使用增长
   - 百万级Skill库可初始化AIX Skill Store

3. **分层记忆 = 三层本体论的另一种表达**
   ```
   L0 Meta规则 → Harness规则
   L1 索引 → 快速路由
   L2 全局事实 → UTXO账本状态
   L3 Skill → Pico Claw能力
   L4 会话归档 → 历史交易记录
   ```

4. **Token高效 = Box低成本运行**
   - <30K上下文 vs 其他Agent的200K-1M
   - 成本低一个数量级
   - 适合Box长期后台运行

5. **自举实证 = 代码可信度**
   - 整个仓库从git init到commit都由Agent自主完成
   - 证明了框架的可行性

**🔧 融合方案**

```
AIX Box内置GenericAgent：
  GenericAgent核心（~3K行）
  + 9原子工具
  + L0-L4分层记忆
  + UTXO账本作为L2全局事实
  + Harness作为L0 Meta规则
  + Coin Hour消费记录作为L4归档
```

**那耶村场景**：

| 村民需求 | GenericAgent第一次做 | 之后每次 |
|---------|---------------------|----------|
| "查本月消费" | 读UTXO账本→计算→返回 | 直接调用Skill |
| "订王五饭馆晚餐" | web_scan查看菜单→下单→支付 | 一句话完成 |
| "帮我卖10个Coin Hour" | 连接交易所→下单→确认 | 直接执行Skill |
| "生成进货报表" | 读账本→汇总→生成PDF | 自动化流程 |

**关键优势**：每个Box用几周后会有独特的Skill树——**那耶村Box的能力和其他村Box不同**，因为村里需求不同，进化路径不同。

**⚠️ 融合障碍**

1. **精度问题**：自主摸索可能有失败，金融操作需要更高确定性
2. **L0 Meta规则必须硬编码**：Coin Hour操作规则不能让Agent自己摸索
3. **L2全局事实应该是UTXO账本**：不能只存在文件里

**🔧 改造方案**

```
L0 Meta规则（硬编码，不可进化）：
  - Coin Hour转账必须UTXO原子校验
  - 关键操作必须ask_user
  - 禁止操作列表（删除账本、改Coin Hour算法）

L2全局事实：
  - 替换为UTXO账本实时状态
  - 每次操作前同步最新账本

L3 Skill可进化区域：
  - 村民常用操作的自动化流程
  - 商户服务对接脚本
  - 报表生成、数据查询等
```

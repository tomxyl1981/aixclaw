──────── Project Summary ────────

### Top Issues

1. **Unhandled network and parsing failures in `evidence_pubmed_connector.py`** — The PubMed adapter makes bare `urllib.request.urlopen` calls with no exception handling for `URLError`, `HTTPError`, socket timeouts, or malformed XML from NCBI. Since this connector is the data source for the entire build pipeline, any transient NCBI glitch aborts the whole build with an uncaught exception.

2. **Incorrect safety ceiling logic in `target_evidence_matrix.py`** — The `SafetyContraindication` check sets `m.safety_ceiling = 0.20`, but the subsequent `has_safety_dim` block unconditionally overwrites it with `0.80` whenever any SAFETY-dimension row exists. Severe SAE/animal-model rows therefore never lower the ceiling, defeating the intended safety gating.

3. **NameError in safety penalty computation (`target_evidence_matrix.py`)** — `safety_penalty = max(0.0, score - m.safety_ceiling)` references `score` before it is assigned on the next line. Any target with a safety ceiling hits `NameError` at runtime, silently breaking the scoring pipeline.

4. **Wrong UniProt mapping for ACVR2B (`chembl_connector.py`)** — ACVR2B is mapped to Q13705 (ACVR2A) instead of P27037, so all ACVR2B queries resolve to the wrong ChEMBL target and produce incorrect mechanism/activity data.

5. **Fabricated direction claims in `evidence_pubmed_connector.py`** — When no direction keyword matches, `EvidenceDirection.UNKNOWN` is silently converted to `"up"`, inventing an upregulation claim from evidence that says nothing about direction. This propagates misleading rows into the evidence graph.

6. **Cross-contradiction guard is dead code (`target_evidence_matrix.py`)** — `_check_cross_contradictions` reads `_parent_matrix`/`_parent_contradictions` from `EvidenceRow`, but those attributes are never set. The `already` dedup guard always returns `None`, so cross-contradictions are never detected or reported.

7. **Pagination broken in `chembl_connector.py`** — ChEMBL returns `next` as a relative path (e.g. `/chembl/api/data/...`). Assigning it directly to `url` makes `urllib.request` resolve against localhost, so multi-page fetches fail after the first page.

8. **`max_phase` can be `None` (`chembl_connector.py`)** — `get_mechanisms` defaults `max_phase_for_ind` to `0` for missing keys, but ChEMBL returns JSON `null` for present keys. `max()` over a generator containing `None` raises `TypeError` for any mechanism with a null phase.

### Module Hotspots

- **`target_evidence_matrix.py`** — 9 comments, including class-definition errors (missing `@dataclass`), duplicated method definitions, dead cross-contradiction logic, and a `NameError`. Highest severity and density.
- **`chembl_connector.py`** — 5 comments mixing data-corruption bugs (wrong UniProt ID), network/type failures, and TLS verification disabled globally.
- **`evidence_pubmed_connector.py`** — 5 comments focused on error handling and data integrity (fabricated direction, dead code).
- **`mom_validator.py`** — 4 comments: SQLite connection leaks, unused `days` parameter, and a confusing pressure metric formula.

### Cross-Cutting Concerns

- **Unhandled external I/O failures** — Both `evidence_pubmed_connector.py` and `chembl_connector.py` call network/parsing code without try/except. NCBI or ChEMBL downtime or malformed responses crash the pipeline. Representative: `evidence_pubmed_connector.py` (`urlopen`), `chembl_connector.py` (`_request` pagination).
- **Silent data corruption** — Multiple places fabricate or misrepresent data: UNKNOWN direction forced to "up" (`evidence_pubmed_connector.py`), wrong UniProt mapping (`chembl_connector.py`), safety ceiling overwritten (`target_evidence_matrix.py`). These produce wrong outputs without any warning.
- **Dead/duplicated code** — `POTENCY_BANDS` unused (`chembl_connector.py`), `fc` parsed but unused (`evidence_pubmed_connector.py`), `compute_interpretability` defined 3× (`target_evidence_matrix.py`), no-op `.replace("e","e")`. Indicates incomplete refactoring.
- **Resource leaks** — `mom_validator.py` opens SQLite connections without `with`/`finally`; exceptions leak connections in a module-level singleton.
- **Misleading defaults** — `chembl_connector.py` `max_phase` `0` default vs `None`, `mom_validator.py` unused `days` parameter. Callers assume behavior that isn't implemented.

### Quick Wins

- Add `@dataclass` decorator to `SafetyContraindication` (`target_evidence_matrix.py`) so `asdict()` works.
- Move `score` assignment before the `safety_penalty` line in `target_evidence_matrix.py`.
- Correct `ACVR2B` mapping from Q13705 to P27037 in `chembl_connector.py`.
- Prepend the ChEMBL API base URL to `page_meta['next']` before assigning to `url` in `chembl_connector.py`.
- Delete the two duplicate `compute_interpretability` definitions in `target_evidence_matrix.py`.
- Remove the unreachable `p.startswith("e-")` branch in `evidence_pubmed_connector.py` and use `min(float(p) for p in p_matches)`.
- Wrap the URL fetches in `evidence_pubmed_connector.py` with a retry loop catching `URLError`/`HTTPError`/`socket.timeout`, and guard `ET.fromstring` with a `ParseError` catch.
- Handle `None` in the `max_phase` generator in `chembl_connector.py` by filtering out `None` items.

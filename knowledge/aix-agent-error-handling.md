# AIX Agent 错误处理机制设计

> 基于 Claude Code / OpenClaw / Hermes Agent 对比分析，2026-05-04

---

## 核心问题

**工具失败后，谁来决定下一步？**

三个框架的答案：
| 框架 | 决策者 | 问题 |
|------|--------|------|
| Claude Code | 程序分类+模型判断 | 模型自主空间被明确边界限制 |
| OpenClaw | 模型完全自主 | 静默挂起600s、级联Fallback失败 |
| Hermes Agent | 重试3次后模型判断 | 静默假完成Bug（Issue #9400） |

---

## 设计原则（四个必须）

### 1. 失败必须分类

```
失败类型
├── 临时性失败（可重试）
│   ├── 网络超时
│   ├── 速率限制 429
│   └── 服务暂时不可用 503
│
└── 确定性失败（直接上报）
    ├── 权限拒绝 403
    ├── 格式错误 400
    ├── 工具不存在
    └── 资源不存在 404
```

**处理策略**：
- 临时性失败：退避重试（指数退避）
- 确定性失败：停止，注入上下文，让用户决定

### 2. 重试必须有上限

**Claude Code的经验**：
- `MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3`
- 来自BigQuery生产数据分析（1,279个会话，最多重试3,272次，每天浪费25万次API调用）
- 不是猜测，是数据推导

**AIX方案**：
```yaml
retry_limits:
  network_timeout: 3
  rate_limit_429: 5  # 有retry-after头，可多试
  service_503: 3
  
circuit_breaker:
  consecutive_failures_threshold: 3
  token_output_threshold: 500  # 连续3次<500 token，主动终止
```

### 3. 失败必须告诉用户

**最危险的设计**：Agent在失败后自己绕路、自己汇报完成

**Hermes Bug案例**（Issue #9400）：
- 工具成功但模型回复空
- 找上一轮旧文字当作最终答案
- 任务未完成但汇报"完成了"
- 用户完全不知道停在半路

**AIX原则**：
```
不可恢复失败 → 停止 → 上报用户 → 等待指令
```

**实现**：
```yaml
error_handling:
  on_irrecoverable:
    action: stop_and_report
    inject_context: true
    user_message: |
      ⚠️ 任务执行遇到不可恢复失败：
      - 失败类型：{error_type}
      - 失败原因：{error_reason}
      - 已尝试：{attempts}次
      请手动处理或提供新指令。
```

### 4. 任务状态与对话历史分离

**OpenClaw问题**：
- 恢复靠删`sessions.json`
- 代价：全部对话历史丢失

**AIX方案**：
```
任务状态持久化
├── 对话历史（可丢失）
│   └── sessions.json
│
└── 任务进度（不可丢失）
    ├── task_state.json      # 当前任务状态
    ├── checkpoint.json      # 检查点
    └── utxo_ledger.json     # UTXO账本（原子性保障）
```

**恢复策略**：
- 对话历史丢失 → 任务进度保留
- 从最后一个checkpoint继续
- UTXO账本保障原子性

## AIX Agent 错误处理架构

```
┌─────────────────────────────────────────────────────────────┐
│                     工具调用失败                              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   第一步：错误分类                            │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐      │
│  │ 网络超时    │    │ 速率限制    │    │ 权限拒绝    │      │
│  │ 503临时    │    │ 429         │    │ 400/403/404 │      │
│  └──────┬──────┘    └──────┬──────┘    └──────┬──────┘      │
│         │                  │                  │              │
│         ▼                  ▼                  ▼              │
│    临时性失败          临时性失败        确定性失败            │
└─────────┬──────────────────┬──────────────────┬─────────────┘
          │                  │                  │
          ▼                  ▼                  ▼
┌─────────────────────────────────────────────────────────────┐
│                   第二步：决策                               │
│                                                              │
│  临时性失败                    确定性失败                    │
│  ├── 检查重试次数              ├── 停止任务                   │
│  ├── 未达上限→退避重试         ├── 注入错误上下文             │
│  └── 达到上限→上报用户         ├── 保存检查点                 │
│                                └── 上报用户等待指令           │
└─────────────────────────────────────────────────────────────┘
          │                                      │
          ▼                                      ▼
┌─────────────────────────────────────────────────────────────┐
│                   第三步：熔断检测                            │
│                                                              │
│  连续失败次数 >= 3？                                          │
│  ├── 是 → 全局熔断，停止所有任务，上报用户                    │
│  └── 否 → 继续执行                                           │
│                                                              │
│  Token产出检测：                                              │
│  连续3次工具调用 < 500 token？                               │
│  └── 是 → 判断"继续无意义"，主动终止                          │
└─────────────────────────────────────────────────────────────┘
          │
          ▼
┌─────────────────────────────────────────────────────────────┐
│                   第四步：状态持久化                          │
│                                                              │
│  任务进度 → task_state.json                                  │
│  检查点   → checkpoint.json                                  │
│  UTXO记录 → utxo_ledger.json                                 │
│                                                              │
│  原则：对话可丢，任务进度不能丢                               │
└─────────────────────────────────────────────────────────────┘
```

## 与UTXO账本结合

**AIX独特优势**：UTXO账本天然支持原子性校验

```yaml
utxo_error_handling:
  on_task_start:
    - 创建UTXO记录：task_id + 预期状态
  
  on_task_success:
    - UTXO标记完成：task_id + 实际状态
    - 原子性写入
  
  on_task_failure:
    - UTXO回滚：task_id + 失败原因
    - 状态可追溯
    - 下次从UTXO检查点恢复
```

**价值**：
- 任务状态不可篡改
- 失败可追溯
- 恢复有据可查

## 避免的已知坑

| 框架 | 问题 | AIX规避方案 |
|------|------|-------------|
| Hermes | 静默假完成 | 成功+回复空 → 视为失败，不找旧文字 |
| OpenClaw | 静默挂起600s | RPC超时 → 主动上报，不静默等待 |
| OpenClaw | 级联Fallback失败 | 模型失败 ≠ Provider失败，隔离冷却 |
| Hermes | 无差别重试3次 | 错误分类，确定性失败不重试 |
